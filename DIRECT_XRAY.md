# Private Line: Telegram → Xray

Рабочая схема после обновления:

- **194.146.223.104**: существующие Telegram-бот, админка, PostgreSQL и платежи.
- **185.236.25.152**: `private-line-node.service` (Python из Ubuntu + Xray 26.6.27), VLESS/TCP/REALITY/Vision на 443.
- API управления на 2096 принимает только основной сервер и localhost. Xray HandlerService слушает только localhost:10085.

Marzban после миграции остановлен, его Docker restart policy выключена. Он больше не участвует в выдаче ключей. Старые файлы и база остаются для восстановления. Существующее значение `protocol=marzban` в основной БД обозначает совместимый API; менять его вручную не нужно. Бот, платежи и UUID не мигрируют в другую БД.

## Обновление

На **основном** сервере:

```bash
cd /opt/private-line
bash update.sh --force-nodes
```

SSH-доступ к ноде уже должен быть сохранён в админке. Обновление не требует CI / GitHub Actions.

Скрипт:

1. Собирает и проверяет основное приложение.
2. Временно исключает ноду из новых назначений, сохраняя выданные ключи.
3. Перед отключением Marzban проверяет настоящий Xray на отдельных loopback-портах: REALITY-туннель, учёт трафика, hot-add/remove, сохранение состояния после рестарта.
4. Блокирует внешние изменения API на время экспорта; переносит UUID, статусы, лимиты, расход трафика и Reality-ключи. Неизвестный протокол, отсутствующий UUID или on-hold пользователь останавливают миграцию до отключения старого процесса.
5. Проверяет TLS целевого SNI и конфигурацию Xray, сохраняет резервную копию, запускает новый сервис. При ошибке локального запуска возвращает прежний процесс.
6. С основного сервера проверяет свежий ключ, его отзыв, постоянный тестовый ключ и существующий оплаченный ключ, если доступен. Только после этого разрешает новые назначения и повторяет незавершённую выдачу по оплаченным заказам.

**`DIRECT XRAY LOCAL PASS` ещё не означает, что внешний VPN работает.** Итоговый результат — `PRODUCTION UPDATE PASS` после внешних HTTPS-проверок. После этого импортируйте полученную в Telegram ссылку `vless://…` в сторонний клиент и проверьте подключение из своей сети. Серверный тест не проверяет блокировки вашего оператора или настройки телефона.

Если приложение использует URL подписки `/sub/…`, после обновления профиль прямого Xray должен появиться в списке серверов. Старую подписку обновите вручную в приложении. Для проверки конкретной ссылки из Telegram на основном сервере: `bash scripts/probe_vless_e2e.sh --telegram-url ID_НОДЫ`. Скрипт запрашивает ссылку скрытым вводом, сверяет её с БД и состоянием ноды, затем проверяет HTTPS через этот же туннель. Не вставляйте VLESS-ссылку в публичные логи и чаты.

Если серверная проверка проходит, а на устройстве соединение всё равно не открывает сайты, проверьте журнал клиентского приложения. Ошибка DNS на `8.8.8.8:853` в Windows sing-box означает, что резолвер клиента не отвечает в его текущей сети; она сама по себе не доказывает неисправность ключа. Попробуйте отключить DNS-over-TLS в настройках клиента, обновить профиль и повторить тест из той же сети. Сравните с другим совместимым клиентом VLESS Reality/Vision без изменения ключа.

## Состояние и восстановление

На ноде:

```bash
systemctl status private-line-node --no-pager
journalctl -u private-line-node -n 50 --no-pager
```

- `/var/lib/private-line-node/state.json` — единственный источник пользователей и настроек; root-only, содержит секреты.
- `/var/lib/private-line-node/backup-*/marzban-export.json` — исходный экспорт до перехода; содержит секреты.
- `/var/lib/private-line-node/core.log` — ограниченный журнал Xray; не публикуйте его без удаления секретов.
- `/opt/private-line-node/agent.py` и `xray` — исполняемый runtime.

Мутации последовательно записываются атомарно с fsync, затем применяются к работающему Xray. Проверяются UUID, flow и наличие/отсутствие пользователя. Ошибка CLI с exit=0 не считается успехом. Обычная выдача/отзыв не перезапускает ядро. При сбое мутации допускается один восстановительный запуск из сохранённого состояния; если он не удался, API возвращает ошибку.

Сервис проверяет лимиты/сроки каждые 2 секунды. При аварийном отключении возможна потеря последних секунд учёта трафика. Удаление запрещает новые подключения; уже открытые потоки не гарантированно обрываются мгновенно. Ограничение количества IP/устройств этот backend не реализует.

Не запускайте старый Marzban одновременно с новым сервисом: оба используют 443/2096. Не восстанавливайте старый экспорт после выдачи новых ключей без сверки: в нём нет последующих изменений. Если внешний E2E не прошёл, нода остаётся недоступной для новых назначений; исправление и повторный `bash update.sh --force-nodes` сохраняют native state и не импортируют устаревший экспорт повторно.

Добавление новых нод через старый installer пока создаёт Marzban-совместимую ноду; следующий запуск `update.sh` переводит зарегистрированную ноду на прямой Xray. Основной сервер исключён из VPN-нод. «Самый быстрый» выбирается по TCP-задержке до VPN-порта с основного сервера; это не замер скорости из сети покупателя.

## Проверки кода

```bash
python -m unittest tests.test_direct_xray
python node/selftest.py --binary /path/to/xray
```

Второй тест использует настоящий pinned Xray, временный локальный TLS-сервер и случайные тестовые UUID. Производственные порты и ключи не используются. Разрешение loopback в его freedom-outbound относится только к тестовому стенду.
